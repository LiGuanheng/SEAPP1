## 轮次 1｜首版开发（WorkBuddy）

- **时间**：2026-10-24
- **委托方**：学生（LiGuanheng）
- **任务来源**：学生上传的《丧尸围城：亡骸君主》最终完整文档（一次性开发任务书 + GDD + SRS + SDD + Git 规范）
- **明确约束（学生原文要点）**：
  1. 一次性完成可玩第一版，不只做规划或静态页面；
  2. Phaser + TypeScript + Vite，桌面浏览器优先；
  3. 按 M0–M5 真实分阶段开发与提交，不伪造历史；
  4. 需要公开线上地址、GitHub 源码、测试结果、课程文档；
  5. 一般技术选择自行判断并记录，只有真正需要授权的操作才询问。
- **AI 使用的工具**：文件读写、终端（npm/git）、无头浏览器（构建与截图验证）、图像生成（仅用于菜单/结局关键视觉）、Vitest。
- **AI 的判断**：
  - V1 范围收敛为 4 兵种 + 1 Boss + 3 前线 + 2 座能源站，避免范围失控（见 DECISIONS D-01、SRS §1.3）。
  - 战斗核心做成可 headless 运行的模拟，以便自动化证明"可通关"。
  - 键位 `W` 冲突（镜头 vs 技能）改为 `Q/E/R` 技能，已标注待验收（D-15）。
- **产出**：
  - 6 个真实里程碑提交（M0 `7c7f1f8` → M5），全部推送到 `origin/main`；未使用 `--force`、未改写历史、未伪造作者。
  - 34 个自动化测试、1 套端到端冒烟脚本、1 个命令行战斗模拟器、GitHub Actions 构建 + Pages 部署。
  - 线上地址 https://liguanheng.github.io/SEAPP1/ （实测 HTTP 200 并可开始新局）。
- **AI 在本轮中自行做过的判断（已记录在 DECISIONS/DEV_LOG）**：
  - 战斗采用流场寻路而非逐单位 A*（性能与"尸潮"手感）。
  - 墙体/建筑视为高代价障碍，单位撞墙即攻击，避免为每个单位写破墙决策。
  - 里程碑内先做可运行版本，再做数值校准；用 headless 模拟（Vitest）证明可胜/可败，而不是靠口头声明。
  - 战场素材程序化绘制而非 AI 生图，以保证多帧一致性与授权干净；AI 仅用于 3 张关键视觉。
  - 无头截图发现 Phaser 失焦暂停会导致"看起来卡住"，加入 `?nopause=1` 与 `advanceFor()` 调试通道（仅测试用）。
- **AI 未能完成 / 需要学生处理的事**：
  - 真实 GPU 上的 FPS 实测（无头软件渲染不可作为依据）。
  - 判断课程评分细则是否满足（任务书未提供）。
  - 最终试玩反馈与是否需要调难度。
- **学生反馈**：**待填写**（请学生在试玩后补充真实意见，例如难度、手感、画面；不要代为编造）。
