## 5. 性能记录

### 5.1 逻辑模拟（可靠指标）

- 场景：终局，347 个单位（含 1 君主化身、1 巨汉）全部投放。
- 方法：在浏览器中同步执行 `sim.update(1/30)` × 1800 次（= 60 秒游戏时间），用 `performance.now()` 计时。
- 结果：**362 ms / 1800 tick = 0.201 ms/tick**，约合 4971 次模拟/秒。
- 结论：逻辑层远低于 16.7 ms 的帧预算，**瓶颈在渲染与精灵同步**，不在战斗 AI/寻路。

### 5.2 同屏单位上限

| 画质 | 普通战 | 终局 |
|---|---:|---:|
| 高 | 260 | 320 |
| 低 | 180 | 220 |

超出上限的库存进入待投放队列（`spawnQueued` 每 0.5 秒重试），不会丢失兵力。

### 5.3 未完成项（诚实标注）

- **未在真实 GPU 环境测得 FPS**。本项目所有自动化运行均在无头软件渲染下完成，其帧率不具备参考价值。
- 需学生在自己的笔记本上以 `npm run dev` 打开，按 `F12` 观察 Chrome FPS，记录"100 / 200 / 300 单位"三档数据并回填本节。
- 若低端设备掉帧，可在设置中切换「低画质」，活动单位上限降至 180/220。

## 6. 已知缺陷与限制

| 编号 | 问题 | 影响 | 计划 |
|---|---|---|---|
| B-01 | 单位在城墙前堆叠成两团，有效攻击面小于理论值 | 破墙时间偏长 | Codex 调分离/编队 |
| B-02 | 疾行者/蛛行者的目标偏好未单独数值验证 | 精锐价值不确定 | 后续补针对性测试 |
| B-03 | 人类 AI 不反攻前线（P1） | 前线一旦占领即永久保有 | 后续版本 |
| B-04 | 无 3× 倍速、无编队（Ctrl/Alt+数字） | 操作便捷性 | P1 |
| B-05 | 终局仪式无独立过场动画 | 演出略突兀 | P1 |
| B-06 | 音效为简单合成音（非专业音效设计），且部分单位攻击无独立音色 | 氛围一般 | P1 提升 |
| B-07 | 无头环境无法验证真机 FPS | 性能数据不完整 | 学生实测回填 |
| B-08 | 移动端/触屏未适配 | 仅桌面可用 | 明确不在 V1 范围 |

> 说明：V1 已有程序化音效（Web Audio 合成，无外部文件），但音色较简单；"设置 → 音效"开关会真实生效。
