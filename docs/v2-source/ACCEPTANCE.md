# 《异界围城：魔物之王》V2 软件工程需求、追溯与验收清单

> 设计文档同 `01_完整游戏设计_GDD.md`；本文件用于课程评价、可测试性与提交记录。状态：**待实现，非测试通过报告**。

## 1. 需求变更原因与边界

- V1（《丧尸围城：亡骸君主》）：多日经营、尸巢繁殖、双阵营每日发展、最终献祭。
- V2：为了更适合课堂短时间展示并突出核心乐趣，聚焦**单场奇幻魔物军团攻城**：开局选魔王/统帅→固定资金买兵→拖放出兵→战中买兵/占领→摧毁中央日轮圣晶或超时/力竭失败。
- V1 代码利用原则：**允许全面重制、模块重写、删除废弃代码和替换全部视觉资源**；仅在实际有助于新版本质量时复用 Phaser、摄像机、战斗、部署、城墙、AI 和测试。取消主流程中的日循环、尸巢升级、每日充能与跨日占领。不强求保留旧版游戏的结构和美术。
- GitHub 历史如实保留，旧版需求与实际版本记录可在 docs/archive 或历史标签中检索，不伪造开发过程。

## 3. 测试用例（每项须记 PASS/FAIL/BLOCKED 和证据）

| Case | 步骤和期望 |
|---|---|
| TC-01 | 新建一局，从菜单依次进选专精、统帅、配兵，无白屏；帮助/返回正常。 |
| TC-02 | 三种专精各测试一次，对应折扣、增强或法术效果确实生效；只能选一个；魔王阵亡不直接失败。 |
| TC-03 | 选四人后第五人不能选；招募费用一次扣除；未招募者专属兵不可购买。 |
| TC-04 | 购买史莱姆一批库存应+40、魔晶-80（无折扣）；岩甲巨人一批+4、魔晶-140；库存显示正确。 |
| TC-05 | 连续快速点击购买，余额不为负、无重复入库；战中买兵成功进入预备队，部署不二次扣费。 |
| TC-06 | 点卡片或拖卡片到合法区按所选批数出兵；把卡拖到圣晶旁非法区提示且不扣钱/库存。 |

| TC-08 | 框选后右键集火指定塔；取消时回到自动作战；全军冲锋不生成额外军力；单位不得长时间卡墙。 |

| TC-12 | 同一守军/塔/据点不能重复奖励；奖励可在战中买兵；无法负钱。 |

## 4. 核心非功能需求

- NFR-01：在测试机器 Chrome/Edge 上实测 200–300 只己方单位的 FPS、内存与操作响应；目标常态 ≥30 FPS，若不达标先降同屏上限，记录设备与数据；无测量不能写“已通过”。
- NFR-02：1280×720 和 1920×1080 下，单位卡、技能、剩余时间可读，鼠标坐标准确。
- NFR-03：P0 不允许重复扣费、错误生成兵力、据点越权出兵、错误胜败；随机种子固定时可复现。
- NFR-04：无大模型 API、无联网对战、无敏感秘钥硬编码；外部素材有许可记录。
- NFR-05：不删除/伪造已有 Git 历史，重大变更形成独立 commit；未经用户授权不进行危险清理或强推。
- NFR-06（新增美术质量验收）：正式战斗画面采用统一、成熟的史诗异世界奇幻风格，帝国城池有合理规模比例、真实防线分层和建筑细节；十类魔物与统帅有明显不同的战场剪影与动作，不以圆圈、色块或海报代替战斗精灵。应提供真实浏览器内的城池全景、百人军团、有效破墙/开火及龙王技能截图，逐项人工检查，并记录两轮视觉改进与资产许可。此条属于主观视觉验收与可观察功能验收的结合，不可用自动构建成功替代。

## 5. 风险清单与验收时顺序

| 风险 | 后果 | 缓解 |
|---|---|---|
| 从“多日”迁移“单场”不完整 | 旧日结算误触发、幽灵存档 | 新状态机/隔离 v2 存储键，完整回归 |
| 批次购买与出兵混淆 | 资金/库存错账 | 独立纯函数及原子事务测试 |
| 300单位寻路和碰撞 | 墙前聚团、掉帧 | 共享导航、限频寻敌和分批出兵 |
| 城墙破坏不刷新路径 | 战局卡死 | 破墙强制更新连通关系测试 |
| 前线部署范围计算错误 | 直接在圣晶旁刷兵 | 连通+敌占+核心禁投区联合校验 |
| 角色与 UI 素材风格不一 | 画面粗糙 | 先视觉样板、再批量制作，来源可审计 |
| 只测逻辑不测浏览器 | 按键失效/拖放错位 | 真机 Chrome E2E+手工全局通关 |

## 6. 课程演示验收包

交付至少：线上游戏链接、仓库与真实 commits、最新版需求与设计、需求追溯、自动测试结果、至少一局完整手工试玩记录、若干关键场景截图、素材来源和一个3–5分钟课堂演示提纲。未实现的功能应明确标出，不准假称完成。
