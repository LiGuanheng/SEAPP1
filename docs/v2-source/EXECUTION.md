## 1. 最终游戏必须长什么样

不是彩色几何形状互相碰撞的小 demo，而是一款**画面精美、整体气质史诗、带浓厚异世界动漫奇幻风的完整 2D 大规模攻城游戏**：
- 人类帝国「圣曜城」有白金石质城墙、宏伟主城门、城楼/街道/魔法炮塔、旗帜、地表装饰、远近层次、宏大的中央日轮圣晶；地图结构漂亮且真的可攻克，不是网格/色块拼图。
- 玩家阵营是原创的魔物王国。史莱姆潮、哥布林、魔狼、射手及六种统帅专属兵**在缩放时外形依然可辨、动画有动感**；大型风暴龙王、岩铠巨王明显高于普通兵种，具有独立造型和重量感。
- 招募界面有**精美角色立绘/统帅卡片**、魔法纹饰和清晰的兵种卡；战斗 HUD 精致、不遮挡战场，出兵/技能/钱/剩余时间一目了然。
- 召唤法阵、地面阴影、跑动/攻击/受击/阵亡反馈、城墙开裂与坍塌、巨王冲撞、风暴龙息、范围治疗、魔导重炮的弹道与爆炸、圣晶胜败动画都必须有**可见且与真实规则匹配**的效果。音效/BGM 经过许可核验，默认有静音开关、可跳过演出。
- **不要直接沿用旧版亡灵僵尸贴图/恐怖暗黑配色充数**，也不要只给同一种小圆点换十种颜色。应确立完整的画面风格体系，再把所有场景统一成这一风格；可以在**高品质2D像素奇幻风或精致2D手绘/动漫风**之间自主选择最能呈现效果的一种（不强制旧 GDD 的 32px tile 约束），但战场单位、地形、UI 必须和谐统一。
- 图形素材可自主选择：自己制作能用于游戏的合法素材、使用明确允许商用/修改/分发的开源资源并注明许可，或使用环境中确实可用的图片生成能力。**不得直接复制《转生史莱姆》、Overlord、红警的角色、美术、音频、Logo 或未授权素材。** 如果素材能力有限，使用高完成度、风格统一的原创图形/动画作为可玩方案，不能拿占位素材谎称精美完成。

**视觉验收关键镜头：** (A) 全景拉远，城池与大军宏观对峙；(B) 100+史莱姆/魔物从法阵分批涌出；(C) 巨王撞碎城墙并引导部队通过；(D) 龙王飞越城池释放有方向感的风暴吐息；(E) 数百魔物与多统帅同时攻向中央圣晶；(F) 具有完成度的胜败过场和战报。要在真实浏览器截图中证明，不是只展示宣传图。


### 1.1 新增最高视觉质量标准：成熟、宏伟、可信的异世界战争，而非小儿科 Demo

**美术导演级要求（在不牺牲可玩性与授权安全的前提下优先实施）：**

- **默认艺术方向**：优先选择**成熟、史诗感的日式异世界奇幻 2D 手绘/精细插画式俯视战场**，兼具建筑厚重感与奇幻魔法色彩。不是幼儿向 Q 版、廉价像素小人、卡通玩具城、平面 PPT 图形或一堆 emoji。若其他统一画风在当前资产条件下显著更好，可以自主采用，但必须达到同样的质感；不要把 3D 写实误当硬性要求。
- **帝国城池必须像有真实防御体系的宏伟要塞**：宽厚多段外城墙、可见垛口/塔楼/门楼、厚重城门、内城堡垒与白金圣殿、纵深街区、供部队通行的道路、军营、魔导炮台、防空法阵、圣光塔、旌旗、断墙和战争废墟。建筑体积、道路宽度、城墙高度与人/巨人/龙的相对比例要合理。画面拉远能够读出“真正的大城与防线”，拉近能看到砖石、窗洞、拱券、炮口、城楼层次、阴影和装饰，而不只是几种贴图复制拼接。
- **帝国防御表现必须可信且可辨**：弓手驻墙、骑士守门、法师远程支援、魔导炮有朝向/蓄能/后坐与弹道、防空塔对飞龙有清楚的追踪与光束、圣光塔对英雄威胁显著；城门和墙段确实阻挡通路，破坏后露出有效缺口；守军在城门、道路、塔旁的布阵应有军事逻辑。**好看必须来自真实可互动的城防，不是背景海报。**
- **玩家军队要像真正的联军**：10种兵不能靠圆圈颜色区分；史莱姆半透明凝胶、哥布林铠甲与武器、魔狼四足奔跑、蜥蜴弓箭手射击，巨人厚重岩甲、飞龙有翼展/高度层次、狼骑具骑乘轮廓、蜘蛛多足移动、树人有树冠与护卫动作，分裂史莱姆有清晰变体。每类至少有方向、地面阴影、移动/攻击/受击/死亡的可辨表现。**大型统帅明显大于常规兵种**，英雄不是普通小兵的简单放大。
- **宏大感来源于构图和战争规模**：战前给一次可跳过的城市全景镜头（城墙、圣晶、魔物军团、旗帜、云雾/光照）；战中区分近景主体、城墙遮挡层、远景建筑；召唤阵沿战线展开，密集军团有前后队列、多个进攻方向与不同兵种节奏；法术、箭雨、炮火、烟尘、碎石和建筑损毁产生分层反馈；胜败时有明确镜头、音效和圣晶演出。对特效做节流，**宁可适度减少无意义粒子，也不要让画面卡顿或主体被特效淹没。**
- **菜单也要像完整商业游戏的界面**：主菜单具备世界观氛围图与清晰标题；魔王专精和六位统帅使用一致的高质量角色卡、肖像、技能图标、特征短句；军队购买和战斗底栏使用统一的魔法金属/羊皮纸体系，信息层级清楚。禁止“默认 HTML 按钮 + 纯色背景 + 技术调试文字”作为正式视觉版本。
- **资产现实性与版权**：优先利用当前环境可生成或合法获取的**真正游戏内资产**，包括层级地图素材、可用于动画的角色帧、UI icon、光效粒子；如使用开放素材，逐条核验许可及署名。不能把立绘直接当作能行走的战场单位，不能用未经许可的商业游戏截图、角色或背景。若受限于绘图资源，集中做**一座完整城门战场 + 若干精美兵种 + 标志性巨王/龙王**，再扩展统一风格，避免铺满粗糙占位。
- **自主视觉迭代不能省**：早期制作“城门 + 两种真实防御塔 + 一队魔物 + 巨王 + 龙王 + 远景圣晶”的**可操作场景**，启动浏览器截图检查比例、色彩、遮挡、视线和动效；完成主体后再至少进行两轮视觉自检（全景与近景），列出3个最像 Demo 的问题并实际修正。只有文本声称“已精美化”不算达成。

**新增四条硬验收**：

1. **城池全景**：截图必须能清楚识别外城门、城墙/塔楼、军事街区、中心高耸的圣晶，整体像一座被军队守卫的奇幻要塞，而不是几排矩形。
2. **军团同框**：真实战场截图应显示至少100个活动魔物（达到更高性能目标后再增加）及两种以上视觉差异明显的兵种，镜头层次和相对尺寸合理，不允许以背景贴图冒充活动单位。
3. **城防互动**：至少展示一处魔导炮/箭塔实战开火和一次破墙后的真实通行；城门、塔楼、士兵驻守位置与道路相互匹配。
4. **双英雄高光**：岩铠巨王破墙、风暴龙王释放定向吐息必须是**真实技能引发的战场效果**，有独立模型/动画/音效或可辨视觉反馈，且命中、伤害与画面一致。

**优先级**：在确保“可完整通关、资源不作弊、出兵与指挥可靠”基础上，宁愿收敛装饰性功能，也要把**一座宏大的帝国城、可信的人类防线、个性鲜明的魔物大军、破城与龙息四个标志性场景**做好。不允许以“功能很多”为理由长期使用廉价占位图。

## 2. 冻结的核心玩法（别自行恢复旧系统）

**开局即最后总攻**，不设计天数、基地经营、尸巢建造、科技升级、多日兵力生产、人类每日发展、能源塔充能减速、跨日占领、复杂第二货币、LLM 人类 AI、联网账号/多人。

1. 主菜单→选择简单/普通/困难→三种魔王专精选一→六名统帅选1–4名→使用魔晶自由购买魔物→单场最终总攻→胜/败/战报与重试。允许预设军团直达战斗，方便课堂演示。
2. 六统帅：**风暴龙王、岩铠巨王、苍月狼王、蛛影女皇、森灵女王、史莱姆帝王**。每名拥有一位真实可部署英雄、独立造型与战斗行为、一种专属兵种购买权、一项需要玩家选目标/方向/范围释放的主动技能。统帅能被杀死、技能有条件和冷却。魔王本体也能部署并手动释放其专精技能。
3. 四通用兵种：**史莱姆、哥布林战士、魔狼、蜥蜴射手**；六统帅专属：**风暴飞龙、岩甲巨人、月影狼骑、潜行毒蛛、树人守卫、分裂史莱姆**。数据驱动；不同兵种速度、血量、攻击方式、敌方克制真实不同；价格和数值按 GDD 做初版并允许基于测试微调。
4. 简单/普通/困难战前分别给3400/2800/2500魔晶；开战时即可部署全部库存，或随时分批部署；战中有限击杀、拆塔、占领奖励增加魔晶，允许继续购买单位形成援军。**购买才扣魔晶；部署只扣真实库存，不能重复扣费/免费复制。**
5. **底部固定战术栏**：魔晶与在场/待部署数量、可滚动兵种卡、购买1/3/更多批、部署1/3/全部、统帅与魔王技能、暂停、倍速、全军冲锋。操作为卡片拖到合法区域松手召唤，也支持点击卡→点击地图；有绿色合法/红色非法的准确预览，非法不消耗库存。鼠标框选、右键移动/集火，Q/W/E/R 对应统帅技能、F 魔王技能，1–3 编队。
6. 地图为**单张精致但可实际游玩的圣曜城**，中央圣晶从开局就可见；城外西/中/东三处合法初始部署方向，至少两条无需特殊统帅即可打穿的地面路线；分段可破坏外墙/内墙、被打破后真实可通行，飞龙可越墙但怕防空。两处可选前线据点被真实占领后开放新的出兵区域，仍不得贴着圣晶偷刷兵。
7. 人类守军为有限、可观察的传统规则AI：步兵/射手/骑士/法师、有限预备队，箭塔/重炮/防空/圣光塔和圣剑骑士长。防守火力足够强，普通难度下不能仅靠大堆低级兵正门无脑通关；战术性的多路佯攻、巨人破墙、侧翼绕后和技能释放应明显更有效。不接入任何模型 API，不需要GPU。
8. **城市正中央的日轮圣晶是唯一最终胜利目标。** 圣晶HP归零立即胜利。战斗倒计时简单720秒、普通600秒、困难480秒，超时失败；全部场上单位、库存、可买兵能力及可召唤手段都没有时判力竭失败。充能UI仅表示固定倒计时，**摧毁任何其他建筑都不得延长时间**。暂停与2×必须有真实一致的仿真计时行为。
9. 保留玩家可以从开场就总攻的自由，不设额外的“解锁最终决战”“必须先杀骑士长”等人工关卡。攻占前线、先摧毁哪座塔均为战术选择，而非硬性前置。

## 3. 独立开发、反复修 bug、继续做改进：不要求用户盯着

用户预计**约7小时后才来验收**，这只是用户不在线的背景，**不是要求你计时等待，也不是保证运行时长**。请从现在立刻开发：在当前工具/执行时长许可内持续推进，尽可能完成 M0–M6；**不要每完成一步就停下来等用户确认，也不要只列待办后结束**。

**默认自主决策**：依赖选择、模块设计、旧代码清理、绘图方案、数值微调、测试改造、常规本地 commit 都自行处理，记录关键取舍。只有涉及外部账号权限/付款、机密、影响仓库外文件、破坏远端历史或确实无法绕过的授权时才询问用户。不要为了一个 UI 字体/一个非关键实现细节打断。

**每阶段采用闭环：实际实现 → lint/typecheck → unit tests → build → 真正打开浏览器试玩/E2E（如工具支持）→ 发现错误 → 定位修复 → 重测 → 截图或日志记录 → Git commit（有权限则 push）→ 继续下一阶段。** 每阶段至少主动执行一次代码审查和使用体验改进（操作反馈、场景观感、战斗节奏、性能），不是测试绿了就停止。

当普通错误发生时先修，再继续；不要把小错误堆给用户。E2E工具或浏览器不可用时，用可执行的仿真/自动化替代，明确未做过真实视觉验收，不能声称已验证浏览器画面。

## 4. 建议的连续开发阶段（可重排；每个大阶段必须有真实 commit）

- **M0 审计与 V2 重制准备**：检查仓库、建立独立开发分支或受控主分支工作流；在 Git 留可回滚锚点；建立 `docs/V2_CHANGELOG.md`、`docs/V2_DECISIONS.md`；删除或归档废弃系统的清理计划。**完成后 commit，若已获 GitHub 推送权限则立即 push**。
- **M1 全面重构可玩核心**：新单场状态机、开局选择/配兵、纯逻辑账本、10分钟倒计时、唯一胜败目标、完整战场流程；旧天数/尸巢/献祭逻辑从游戏中真实退出，可直接移除不用的实现。阶段测试与 commit/push。
- **M2 攻城深度**：十兵种与六统帅招募/专属权限；战前战中购买；底部卡片拖放/批量出兵；框选右键、两前线据点、分段破墙、寻路刷新；人工 AI 城防。阶段测试与 commit/push。
- **M3 英雄与战术效果**：六个可玩家手动控制释放的真实统帅技能、三个魔王专精、人类克制、有限增援；完整三档难度；平衡多种通关阵容，避免一个无脑战术碾压。阶段测试与 commit/push。

## 5. GitHub 与用户不在线的处理

1. **每完成一个主要阶段就做一次真实、意义清晰的 Git commit，不要等最终一次性提交。** 如果当前环境已配置了 remote 与推送权限，则**完成每阶段后直接 `git push`**，不要只提醒；若因为权限/网络无法 push，则在本地完成 commit 并继续开发，最后列出每个提交哈希及最简单的推送命令。千万不要谎称已经 push。
2. 不要使用 `git push --force`、更改旧提交日期、伪造通过率、伪造截图或删除 Git 历史。必要时安全归档旧 V1 游戏，只保留可回溯的 Git 历史；无需保留旧版运行路径。
3. 如果 CI/Pages 凭据需要授权，不能以它为理由停止所有本地开发；先做到本地完整可玩，记录阻塞项。没有实际完成远端部署则明确说“未部署”。
4. 中途如模型/执行环境因上下文或时长限制必须结束，**必须先将已验证的工作提交为真实 Git commit**，并在 `docs/V2_PROGRESS.md` 清楚写下已完成、真实测试证据、剩余缺陷、下一步精确操作，方便无缝续跑。不要承诺后台继续执行或等待用户起床再做。
