# V3.2 自主攻城与精确批次

依据最新用户纠正：轨迹只表达大致方向，应清理附近所有可攻击建筑，受到攻击必须反击；每次部署严格遵守所选批数。

已实现：宽范围进攻路线，普通城区/资源/军事建筑均参与搜索，清完终点附近目标才停下；记录真实守军及塔弹来源，受袭与附近友军反击，保留原命令并在交战后继续，待命反击后归位。仍保留真实射程、视线和防止远距离诱敌的边界。修复精灵咏唱用建筑中心判断而导致边缘射程反复取消。

默认1批，普通长按不重复；点放、拖放、快捷按钮都遵守所选批数，移除Shift隐式全下。只有明确选择全部库存/全军按钮才全投。勾选“长按连下”才在600ms后开始，每500ms投一次所选批数，松开停止。

首阶段：97项模型测试、13项真实Chrome精确批次/路线/受袭警报验收通过；已生产构建并实际启动。测试使用隔离目标的单元场景与真实完整战场分别验证，未混作通关证据。报告脚本一次因循环对象序列化失败而未保存，修复后重跑并成功落盘。

待完成：完整生产战役、性能回归、文档同步及公开部署核验。当前不宣称已发布3.2。

追加修复：路线终点避免每帧全量重搜；无遮挡时直接行走，受阻时共享路点，避免300个阵型位置挤爆寻路缓存。增加寻路性能用例与集火目标死亡后保留反击记忆用例，最终100项模型通过。首次300方向进攻13.03FPS的失败JSON保留，独立路线采样修复后重测。

最终本地验收：100项模型、13项出兵/自主作战、10项完整战役通过；驻留、方向进攻与自动攻城三段性能均通过，首次13.03FPS失败数据保留。当前开始正常合入main与公开发布核验。
